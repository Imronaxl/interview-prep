# Топ-100 Linux-команд для DevOps-собеседований

Отсортировано по приоритету — от того, что спрашивают почти всегда, до узкоспециальных команд. Для каждой: что делает, как устроено "под капотом", 2-3 примера.

---

## Уровень 1 — база, спрашивают почти всегда (1-20)

**1. `ls`** — список содержимого директории
Под капотом: системный вызов `readdir()` читает записи каталога (имя файла + номер inode) из блоков данных директории. Без `-l` не вызывает `stat()` на каждый файл — поэтому быстрее.
```bash
ls -la /etc          # все файлы включая скрытые, подробный вывод
ls -lh                # размеры в человекочитаемом виде (K/M/G)
ls -lt                # сортировка по времени изменения
```

**2. `cd`** — смена текущей директории
Под капотом: встроенная команда шелла (не отдельный бинарник — не может им быть, т.к. должна менять cwd самого процесса шелла), вызывает syscall `chdir()`, меняющий указатель текущей директории в таблице процессов ядра.
```bash
cd -                  # вернуться в предыдущую директорию
cd ~                  # домашняя директория
cd ..                 # на уровень выше
```

**3. `pwd`** — показать текущую директорию
Под капотом: `getcwd()` — ядро восстанавливает полный путь, поднимаясь по `..` от текущего inode до корня.
```bash
pwd
pwd -P                # физический путь, без учёта симлинков
```

**4. `cat`** — вывести содержимое файла
Под капотом: последовательное чтение через `read()` блоками и запись в stdout через `write()` — простой поток данных без буферизации для просмотра.
```bash
cat file.txt
cat file1 file2 > combined.txt   # объединить файлы
cat -n file.txt                  # с номерами строк
```

**5. `grep`** — поиск текста по паттерну
Под капотом: построчное чтение, компиляция regex в конечный автомат (DFA/NFA), у GNU grep есть оптимизация Бойера-Мура для литеральных подстрок без спецсимволов — поэтому простой текстовый поиск быстрее, чем сложный regex.
```bash
grep -r "ERROR" /var/log/         # рекурсивно по директории
grep -v "DEBUG" app.log           # инвертировать — исключить совпадения
grep -c "success" access.log      # посчитать количество совпадений
```

**6. `find`** — поиск файлов по критериям
Под капотом: рекурсивный обход дерева через `readdir()`+`stat()` на каждую запись, применяет дерево условий (`-name`, `-mtime` и т.д.) к каждому найденному файлу.
```bash
find /var/log -name "*.log" -mtime +7        # логи старше 7 дней
find . -type f -size +100M                    # файлы больше 100МБ
find /tmp -name "*.tmp" -exec rm {} \;         # найти и удалить
```

**7. `chmod`** — изменить права доступа
Под капотом: syscall `chmod()`/`fchmodat()` обновляет биты режима в inode файла.
```bash
chmod 755 script.sh        # rwxr-xr-x
chmod +x deploy.sh         # добавить право исполнения
chmod -R 644 /var/www      # рекурсивно на директорию
```

**8. `chown`** — изменить владельца/группу
Под капотом: syscall `chown()` меняет поля uid/gid в inode, требует root или CAP_CHOWN.
```bash
chown user:group file.txt
chown -R www-data:www-data /var/www
```

**9. `ps`** — статус процессов
Под капотом: читает из `/proc` — виртуальной файловой системы, генерируемой ядром "на лету" (каждый PID имеет `/proc/[pid]/stat`, `/proc/[pid]/status`, `/proc/[pid]/cmdline`).
```bash
ps aux                     # все процессы, подробно
ps aux | grep nginx        # найти конкретный процесс
ps -ef --forest             # дерево процессов
```

**10. `top`** — процессы в реальном времени
Под капотом: периодически читает `/proc`, считает CPU% как разницу тиков CPU из `/proc/[pid]/stat` между двумя замерами, делённую на прошедшее время.
```bash
top                    # интерактивный режим
top -u www-data         # только процессы пользователя
top -b -n 1             # один снимок, без интерактива (для скриптов)
```

**11. `htop`** — улучшенная интерактивная версия `top`
Под капотом: тоже читает `/proc`, но с ncurses-интерфейсом, деревом процессов, мышью и цветовой индикацией.
```bash
htop
htop -u root
```

**12. `kill`** — отправить сигнал процессу
Под капотом: syscall `kill()` — не убивает напрямую, а доставляет сигнал; что делать с сигналом решает сам процесс (если не перехватывает — ядро применяет действие по умолчанию).
```bash
kill 1234              # SIGTERM (15) — попросить завершиться
kill -9 1234            # SIGKILL — принудительно
kill -HUP 1234           # часто используется как "перечитай конфиг"
```

**13. `killall`** — убить процессы по имени
Под капотом: сканирует `/proc`, сопоставляя поле `comm` (имя процесса) с заданным, шлёт сигнал каждому совпадению.
```bash
killall nginx
killall -9 python3
```

**14. `df`** — свободное место на файловых системах
Под капотом: syscall `statvfs()`/`statfs()` на каждую смонтированную ФС — драйвер файловой системы отдаёт данные о занятых/свободных блоках.
```bash
df -h                   # человекочитаемо
df -i                    # использование inode, не байт
df -h /var                # для конкретного раздела
```

**15. `du`** — размер файлов/директорий на диске
Под капотом: рекурсивный `stat()`, суммирует `st_blocks` (реально выделенные блоки на диске), а не логический размер файла — поэтому может отличаться от `ls -l` (sparse-файлы, дыры).
```bash
du -sh /var/log            # суммарно по директории
du -sh /var/log/*           # по каждой поддиректории
du -h --max-depth=1 /       # на один уровень вглубь
```

**16. `cp`** — копировать файлы
Под капотом: цикл `open`+`read`+`write`, современный coreutils может использовать `copy_file_range()`/`sendfile()` для zero-copy в пределах одной ФС.
```bash
cp -r dir1/ dir2/           # рекурсивно
cp -p file1 file2            # сохранить атрибуты (время, права)
cp -v *.log /backup/          # с выводом что копируется
```

**17. `mv`** — переместить/переименовать
Под капотом: если в пределах одной ФС — syscall `rename()`, атомарная операция, просто перепривязка записи в директории без копирования данных; между разными ФС — фактическое копирование + удаление оригинала.
```bash
mv old.txt new.txt
mv file.txt /backup/
mv *.log /var/log/archive/
```

**18. `rm`** — удалить файл
Под капотом: syscall `unlink()` — убирает запись из директории и уменьшает счётчик ссылок inode; данные освобождаются только когда счётчик доходит до нуля и файл никем не открыт.
```bash
rm file.txt
rm -rf /tmp/build/          # рекурсивно и без подтверждений — осторожно
rm -i *.log                  # с подтверждением на каждый файл
```

**19. `mkdir`** — создать директорию
Под капотом: syscall `mkdir()` создаёт новый inode типа "директория" с записями `.` и `..`.
```bash
mkdir new_folder
mkdir -p a/b/c               # создать всю цепочку сразу
```

**20. `touch`** — создать пустой файл / обновить время
Под капотом: `utimensat()` обновляет atime/mtime существующего файла, либо `open()` с флагом `O_CREAT`, если файла не было.
```bash
touch file.txt
touch -d "2026-01-01" file.txt   # выставить конкретную дату
```

## Уровень 2 — текстовые утилиты и скрипты (21-38)

**21. `less`** — постраничный просмотр файла
Под капотом: читает файл лениво (не грузит весь в память как исторически делал `more`), поддерживает прокрутку назад через seek по файлу.
```bash
less big.log
less +F app.log         # режим как tail -f, live-обновление
```

**22. `man`** — справочные страницы
Под капотом: форматирует groff/troff-исходники man-страницы через `nroff`, передаёт результат в pager (обычно `less`).
```bash
man grep
man -k network            # поиск man-страниц по ключевому слову
```

**23. `awk`** — обработка текста по полям
Под капотом: построчный интерпретатор — читает запись, разбивает на поля по разделителю (по умолчанию пробел), применяет правила `паттерн {действие}` к каждой записи. Фактически маленькая встроенная VM.
```bash
awk '{print $1}' access.log            # первое поле каждой строки
awk -F: '{print $1}' /etc/passwd        # с явным разделителем ":"
awk '$3 > 100 {print $0}' data.txt       # условие на числовое поле
```

**24. `sed`** — потоковый редактор
Под капотом: читает построчно в "pattern space", применяет команды скрипта (`s///`, `d`, `p`), не интерактивен, проход за один раз.
```bash
sed 's/foo/bar/' file.txt              # заменить первое вхождение в строке
sed 's/foo/bar/g' file.txt              # заменить все вхождения
sed -i '/^#/d' config.conf               # удалить строки-комментарии на месте
```

**25. `cut`** — извлечь колонки
Под капотом: построчное разбиение по разделителю или позиции байт/символов.
```bash
cut -d',' -f1,3 data.csv          # 1 и 3 поле через запятую
cut -c1-10 file.txt                 # первые 10 символов каждой строки
```

**26. `sort`** — сортировка строк
Под капотом: на больших файлах использует внешнюю сортировку слиянием (разбивает на чанки, сортирует каждый в памяти, сливает) — не грузит весь файл в RAM.
```bash
sort file.txt
sort -n numbers.txt              # числовая сортировка
sort -k2 -t',' data.csv           # по второй колонке, разделитель запятая
```

**27. `uniq`** — убрать соседние повторы
Под капотом: сравнивает только с ПРЕДЫДУЩЕЙ строкой — для полной дедупликации сначала нужен `sort`.
```bash
sort file.txt | uniq              # убрать все дубликаты
uniq -c file.txt                    # посчитать количество повторов
```

**28. `wc`** — подсчёт строк/слов/байт
Под капотом: последовательный проход, счётчик переносов строк / whitespace-разделённых токенов / байт.
```bash
wc -l file.txt          # количество строк
wc -w file.txt           # количество слов
cat file.txt | wc -c      # количество байт
```

**29. `head`** — первые N строк
Под капотом: читает и останавливается, как только набрано N строк — не читает весь файл.
```bash
head -n 20 file.log
head -c 100 file.txt      # первые 100 байт
```

**30. `tail`** — последние N строк
Под капотом: для `-f` использует `inotify` (Linux) — подписывается на события записи в файл, а не опрашивает файл в цикле.
```bash
tail -n 50 app.log
tail -f /var/log/syslog           # живой просмотр новых записей
tail -f app.log | grep ERROR       # живой фильтр ошибок
```

**31. `xargs`** — построение команд из stdin
Под капотом: батчит аргументы с учётом лимита ядра `ARG_MAX` на длину командной строки — если аргументов слишком много, разбивает на несколько вызовов.
```bash
find . -name "*.tmp" | xargs rm         # удалить все найденные файлы
echo "1 2 3" | xargs -n1 echo            # по одному аргументу за вызов
cat urls.txt | xargs -I{} curl -O {}      # скачать каждый URL из файла
```

**32. `tee`** — дублировать поток в файл и stdout
Под капотом: читает stdin, пишет в stdout И в файл(ы) одновременно — простой fan-out через несколько `write()`.
```bash
echo "test" | tee output.txt              # вывести и записать
command | tee -a log.txt                    # дописать (append) в конец
ps aux | tee processes.txt | grep nginx      # сохранить и одновременно отфильтровать
```

**33. `echo`** — вывод текста
Под капотом: встроенная команда шелла (есть и внешний `/bin/echo`).
```bash
echo "Hello"
echo $PATH
echo -e "line1\nline2"          # интерпретировать escape-последовательности
```

**34. `printf`** — форматированный вывод
Под капотом: как C `printf`, больше контроля над форматом, чем у `echo`.
```bash
printf "%s: %d\n" "count" 42
printf "%-10s|%5d\n" "name" 100
```

**35. `tr`** — замена/удаление символов
Под капотом: посимвольное отображение по таблице замен.
```bash
echo "hello" | tr 'a-z' 'A-Z'         # в верхний регистр
tr -d '\n' < file.txt                    # убрать переносы строк
```

**36. `diff`** — сравнение файлов
Под капотом: вычисляет минимальный набор изменений через алгоритм на основе longest common subsequence (в GNU diff — алгоритм Майерса).
```bash
diff file1.txt file2.txt
diff -u old.conf new.conf              # unified-формат, как в git diff
diff -r dir1/ dir2/                       # рекурсивно по директориям
```

**37. `wget`** — загрузка файлов по HTTP/FTP
Под капотом: неинтерактивный клиент, поддерживает докачку (заголовок Range) и рекурсивную загрузку сайтов.
```bash
wget https://example.com/file.tar.gz
wget -c https://example.com/big.iso        # докачать прерванную загрузку
wget -r -np https://example.com/docs/        # рекурсивно, без ухода выше
```

**38. `curl`** — универсальный сетевой клиент
Под капотом: построен на библиотеке libcurl, поддерживает огромное число протоколов, не только HTTP.
```bash
curl -I https://example.com                # только заголовки ответа
curl -X POST -d '{"key":"val"}' -H "Content-Type: application/json" https://api.example.com
curl -o file.zip https://example.com/file.zip
```

## Уровень 3 — мониторинг и диагностика системы (39-56)

**39. `free`** — использование памяти
Под капотом: читает `/proc/meminfo` — виртуальный файл со статистикой памяти, генерируемый ядром.
```bash
free -h
free -s 5           # обновлять каждые 5 секунд
```

**40. `vmstat`** — статистика виртуальной памяти
Под капотом: читает `/proc/stat`, `/proc/meminfo`, `/proc/vmstat` с заданным интервалом.
```bash
vmstat 2 5           # 5 замеров с интервалом 2 сек
```

**41. `iostat`** — статистика ввода-вывода по устройствам
Под капотом: читает `/proc/diskstats`.
```bash
iostat -x 2                  # расширенная статистика каждые 2 сек
```

**42. `sar`** — историческая системная статистика (пакет sysstat)
Под капотом: фоновый демон `sadc` периодически пишет метрики в бинарные файлы, `sar` читает их обратно для отчёта.
```bash
sar -u 1 5              # загрузка CPU, 5 замеров
sar -r                    # использование памяти за сегодня
```

**43. `uptime`** — время работы системы и load average
Под капотом: читает `/proc/uptime` и `/proc/loadavg`.
```bash
uptime
```

**44. `w`** — кто в системе и что делает
Под капотом: читает `/var/run/utmp` и данные CPU по сессиям из `/proc`.
```bash
w
```

**45. `who`** — залогиненные пользователи
Под капотом: читает файл `utmp`.
```bash
who
```

**46. `lsof`** — список открытых файлов
Под капотом: обходит символические ссылки `/proc/[pid]/fd/` для каждого процесса, сопоставляя дескрипторы с реальными файлами/сокетами.
```bash
lsof -i :8080              # кто слушает порт 8080
lsof -u www-data             # файлы, открытые пользователем
lsof /var/log/syslog          # кто держит открытым конкретный файл
```

**47. `strace`** — трассировка системных вызовов
Под капотом: использует syscall `ptrace()` для перехвата каждого входа/выхода в системный вызов трассируемого процесса — большие накладные расходы, но мощный инструмент отладки.
```bash
strace ls                          # трассировать команду целиком
strace -p 1234                       # подключиться к работающему процессу
strace -c ls                          # сводная статистика по вызовам
```

**48. `netstat`** — сетевые соединения (устаревший)
Под капотом: читает `/proc/net/tcp`, `/proc/net/udp`.
```bash
netstat -tulpn         # слушающие порты с PID процесса
```

**49. `ss`** — современная замена netstat
Под капотом: получает данные из ядра через netlink-сокеты напрямую, быстрее парсинга `/proc/net/*`.
```bash
ss -tulpn                     # слушающие TCP/UDP порты
ss -s                           # сводная статистика соединений
```

**50. `nice`** — запустить процесс с изменённым приоритетом
Под капотом: задаёт стартовое значение nice (-20…19), влияет на вес процесса в расчётах планировщика CPU.
```bash
nice -n 10 ./heavy_script.sh          # низкий приоритет
```

**51. `renice`** — изменить приоритет уже запущенного процесса
Под капотом: syscall `setpriority()`.
```bash
renice -n 5 -p 1234
```

**52-54. `jobs` / `fg` / `bg`** — управление фоновыми задачами шелла
Под капотом: шелл сам отслеживает свои дочерние процессы; `fg` посылает SIGCONT и ждёт завершения, `bg` — SIGCONT без ожидания.
```bash
sleep 100 &        # запустить в фоне
jobs                 # список фоновых задач
fg %1                 # вернуть задачу 1 на передний план
```

**55. `nohup`** — процесс, невосприимчивый к SIGHUP
Под капотом: игнорирует сигнал SIGHUP (посылается при закрытии терминала), перенаправляет вывод в `nohup.out`, если не перенаправлен явно.
```bash
nohup ./long_process.sh &
nohup python3 server.py > output.log 2>&1 &
```

**56. `watch`** — периодический повтор команды
Под капотом: цикл вызова команды с заданным интервалом, очистка экрана между запусками.
```bash
watch -n 2 'docker ps'                # каждые 2 сек
watch -d free -h                        # с подсветкой изменений
```

## Уровень 4 — сеть (57-69)

**57. `ping`** — проверка доступности хоста
Под капотом: ICMP Echo Request/Reply, требует raw-сокет (исторически — root/setuid, сейчас часто CAP_NET_RAW).
```bash
ping -c 4 google.com          # 4 пакета и остановиться
ping -i 0.2 8.8.8.8              # интервал 0.2 сек между пакетами
```

**58. `traceroute`** — маршрут до хоста
Под капотом: шлёт пакеты с увеличивающимся TTL; каждый роутер, где TTL истёк, шлёт обратно ICMP Time Exceeded, раскрывая хоп.
```bash
traceroute google.com
traceroute -n google.com          # без резолва DNS (быстрее)
```

**59. `dig`** — DNS-запросы
Под капотом: отправляет DNS-запрос напрямую (обычно UDP порт 53) к указанному/системному резолверу.
```bash
dig google.com
dig @8.8.8.8 google.com MX          # запрос конкретного типа записи к конкретному серверу
dig +short google.com                 # только IP, без подробностей
```

**60. `nslookup`** — DNS-запросы (устаревающий, но частый вопрос)
Под капотом: аналогично `dig`, но другой формат вывода.
```bash
nslookup google.com
```

**61. `ip`** — настройка сети (современная замена ifconfig/route)
Под капотом: взаимодействует с ядром через netlink-сокеты.
```bash
ip a                     # показать интерфейсы и адреса
ip route                  # таблица маршрутизации
ip link set eth0 up         # поднять интерфейс
```

**62. `ifconfig`** — устаревшая настройка интерфейсов
Под капотом: использует более старые `ioctl()`-вызовы.
```bash
ifconfig eth0
```

**63. `ssh`** — защищённая удалённая оболочка
Под капотом: устанавливает зашифрованное соединение (обмен ключами + симметричный шифр после хендшейка, похоже на TLS) поверх TCP, порт 22 по умолчанию.
```bash
ssh user@host
ssh -i ~/.ssh/id_ed25519 user@host        # с конкретным ключом
ssh -L 8080:localhost:80 user@host          # проброс порта
```

**64. `scp`** — копирование файлов через SSH
Под капотом: в современном OpenSSH по умолчанию использует подсистему SFTP под капотом.
```bash
scp file.txt user@host:/remote/path/
scp -r dir/ user@host:/remote/path/
```

**65. `rsync`** — эффективная синхронизация файлов
Под капотом: алгоритм дельта-передачи (rolling checksum), сравнивает блоки файлов и передаёт только изменившиеся части, а не файл целиком.
```bash
rsync -avz src/ user@host:/dest/          # архивный режим, сжатие
rsync -avz --delete src/ dest/               # с удалением лишнего в dest
```

**66. `nc` (netcat)** — универсальный TCP/UDP-инструмент
Под капотом: открывает сырой сокет, может работать и клиентом, и слушателем — "швейцарский нож" для проверки связи вручную.
```bash
nc -zv host 80              # проверить, открыт ли порт
nc -l 1234                    # слушать порт (простой сервер)
echo "test" | nc host 1234      # отправить данные
```

**67. `iptables`** — правила фильтрации трафика (netfilter)
Под капотом: настраивает цепочки правил ядра (INPUT/OUTPUT/FORWARD), правила применяются последовательно сверху вниз.
```bash
iptables -L -n              # показать правила
iptables -A INPUT -p tcp --dport 22 -j ACCEPT     # разрешить SSH
```

**68. `ufw`** — упрощённый фронтенд к iptables/nftables
Под капотом: генерирует правила iptables/nftables за пользователя.
```bash
ufw allow 22
ufw status
```

**69. `host`** — простой DNS-запрос
Под капотом: аналогично dig, минималистичный вывод.
```bash
host google.com
```

## Уровень 5 — система, сервисы, пакеты (70-85)

**70. `systemctl`** — управление systemd
Под капотом: отправляет команды через D-Bus интерфейс systemd (PID 1).
```bash
systemctl status nginx
systemctl restart nginx
systemctl enable nginx        # автозапуск при старте системы
```

**71. `journalctl`** — чтение логов systemd
Под капотом: читает бинарный структурированный журнал systemd (обычно `/var/log/journal`), не текстовый формат, как классический syslog.
```bash
journalctl -u nginx -f          # живой просмотр логов сервиса
journalctl --since "1 hour ago"
journalctl -p err                 # только ошибки
```

**72. `apt`** — пакетный менеджер Debian/Ubuntu
Под капотом: резолвит зависимости, скачивает `.deb` из настроенных репозиториев, вызывает `dpkg` для фактической установки.
```bash
apt update && apt upgrade
apt install nginx
apt remove --purge nginx
```

**73. `yum` / `dnf`** — пакетный менеджер RPM-дистрибутивов (RHEL/Fedora/CentOS)
Под капотом: dnf — современный преемник yum с более быстрым резолвером зависимостей (libsolv).
```bash
dnf install nginx
dnf update
```

**74. `crontab`** — управление плановыми задачами
Под капотом: демон cron читает файлы `/var/spool/cron/crontabs/[user]`, просыпается раз в минуту и проверяет, какие задачи пора запустить.
```bash
crontab -e                       # редактировать расписание
crontab -l                        # показать текущее расписание
# * * * * * — минута час день месяц день_недели
```

**75. `mount`** — подключить файловую систему
Под капотом: syscall `mount()` присоединяет ФС к точке монтирования, слой VFS ядра дальше маршрутизирует вызовы к нужному драйверу.
```bash
mount /dev/sdb1 /mnt/data
mount -a                            # смонтировать всё из /etc/fstab
```

**76. `umount`** — отключить файловую систему
Под капотом: syscall `umount()`, падает с ошибкой "busy", если есть открытые файлы, если не форсировать.
```bash
umount /mnt/data
umount -l /mnt/data          # ленивое размонтирование
```

**77. `fdisk`** — редактор таблицы разделов
Под капотом: напрямую редактирует секторы таблицы разделов диска (MBR/GPT).
```bash
fdisk -l                    # список разделов
fdisk /dev/sdb                # интерактивное редактирование
```

**78. `lsblk`** — список блочных устройств
Под капотом: читает из `/sys/block` и метаданные udev.
```bash
lsblk
lsblk -f          # с информацией о файловых системах
```

**79. `useradd`** — создать пользователя
Под капотом: меняет `/etc/passwd`, `/etc/shadow`, `/etc/group`, создаёт домашнюю директорию.
```bash
useradd -m -s /bin/bash newuser
```

**80. `usermod`** — изменить существующего пользователя
```bash
usermod -aG docker newuser        # добавить в группу docker
```

**81. `passwd`** — сменить пароль
Под капотом: обновляет хэш пароля в `/etc/shadow` (через `crypt()` с солью).
```bash
passwd
passwd -l username          # заблокировать аккаунт
```

**82. `sudo`** — выполнить команду от имени другого пользователя (обычно root)
Под капотом: после аутентификации проверяет политику в `/etc/sudoers`, логирует вызов в syslog/auth.log для аудита.
```bash
sudo systemctl restart nginx
sudo -u www-data whoami
```

**83. `su`** — переключиться на другого пользователя
Под капотом: запускает новый шелл от имени целевого пользователя, требует его пароль (кроме случая, когда сам root).
```bash
su - postgres
```

**84. `shutdown`** — остановка/перезагрузка системы
Под капотом: сообщает init/systemd корректно завершить работу — сигналы всем процессам, размонтирование ФС.
```bash
shutdown -h now
shutdown -r +5          # перезагрузка через 5 минут
```

**85. `dmesg`** — сообщения ядра
Под капотом: ядро хранит их в кольцевом буфере фиксированного размера в памяти (загрузочные сообщения, события железа, логи драйверов).
```bash
dmesg | tail -50
dmesg -T          # с человекочитаемыми таймстампами
```

## Уровень 6 — DevOps-инструменты (86-100)

**86. `docker`** — CLI контейнерного движка
Под капотом: обращается к демону `dockerd` через Unix-сокет/API, который использует containerd и runc для фактического создания namespaces и cgroups контейнера.
```bash
docker ps -a
docker logs -f container_name
docker exec -it container_name bash
```

**87. `docker-compose`** — оркестрация многоконтейнерных приложений
Под капотом: транслирует сервисы из YAML в вызовы Docker API (создать сеть, создать/запустить контейнеры в порядке зависимостей).
```bash
docker-compose up -d
docker-compose logs -f app
docker-compose down -v          # остановить и удалить volumes
```

**88. `kubectl`** — CLI Kubernetes
Под капотом: отправляет REST API запросы к kube-apiserver, который хранит желаемое состояние в etcd, а контроллеры приводят реальное состояние в соответствие.
```bash
kubectl get pods
kubectl logs -f pod_name
kubectl apply -f deployment.yaml
```

**89. `git`** — система контроля версий
Под капотом: хранит объекты (blob/tree/commit) в `.git/objects`, адресуемые по SHA-хэшу содержимого — это content-addressable файловая система/DAG, а не построчный diff-трекер.
```bash
git log --oneline --graph
git stash && git stash pop
git bisect start          # бинарный поиск бага по истории коммитов
```

**90. `tar`** — архивация файлов
Под капотом: формат "tape archive" (изначально для ленточных накопителей), сам по себе не сжимает — обычно комбинируется с компрессором.
```bash
tar -czvf archive.tar.gz dir/         # создать, gzip-сжатие
tar -xzvf archive.tar.gz               # распаковать
tar -tvf archive.tar.gz                 # посмотреть содержимое без распаковки
```

**91. `gzip`** — сжатие файлов
Под капотом: алгоритм DEFLATE (комбинация LZ77 + кодирование Хаффмана).
```bash
gzip file.txt              # сжать (заменяет оригинал на .gz)
gunzip file.txt.gz           # распаковать
zcat file.txt.gz              # посмотреть содержимое без распаковки на диск
```

**92. `ssh-keygen`** — генерация SSH-ключей
Под капотом: генерирует пару приватный/публичный ключ (RSA/Ed25519), приватный остаётся локально (можно зашифровать паролем), публичный раздаётся на серверы в `authorized_keys`.
```bash
ssh-keygen -t ed25519 -C "email@example.com"
ssh-copy-id user@host          # скопировать публичный ключ на сервер
```

**93. `env`** — переменные окружения
Под капотом: часто используется в shebang (`#!/usr/bin/env python3`) для поиска интерпретатора через `$PATH`, а не жёсткого пути.
```bash
env                              # показать все переменные окружения
env VAR=value command             # запустить команду с доп. переменной
```

**94. `export`** — сделать переменную частью окружения
Под капотом: без `export` переменная видна только текущему шеллу, с `export` — передаётся всем дочерним процессам.
```bash
export DATABASE_URL="postgresql://localhost/db"
export PATH=$PATH:/opt/tools/bin
```

**95. `alias`** — сокращение для команды
Под капотом: разворачивается самим шеллом до выполнения, не отдельный процесс.
```bash
alias ll='ls -la'
alias gs='git status'
```

**96. `history`** — история команд
Под капотом: список команд в памяти шелла, сохраняется в `~/.bash_history` при выходе.
```bash
history | grep docker
!523                    # повторить команду номер 523 из истории
```

**97. `which`** — где находится исполняемый файл
Под капотом: ищет по директориям в `$PATH` по порядку, возвращает первое совпадение.
```bash
which python3
which -a python           # все совпадения, не только первое
```

**98. `ln`** — создание ссылок
Под капотом: без `-s` — hard link (новая запись каталога, тот же inode); с `-s` — symbolic link (отдельный файл с путём).
```bash
ln -s /opt/app/current /opt/app/latest      # симлинк
ln file.txt file2.txt                          # hard link
```

**99. `file`** — определить тип файла
Под капотом: не смотрит на расширение — анализирует magic-байты/сигнатуру заголовка файла по базе `/usr/share/file/magic`.
```bash
file archive.tar.gz
file binary_without_extension
```

**100. `stat`** — подробные метаданные файла
Под капотом: напрямую читает структуру inode через syscall `stat()` — номер inode, права, время создания/изменения/доступа, количество блоков.
```bash
stat file.txt
stat -c "%a %n" *.sh          # только права в восьмеричном виде + имя
```
