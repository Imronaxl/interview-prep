# Как использовать этот файл

Промпт для ИИ-агента с доступом к файловой системе, сборке и запуску (Claude Code или аналог). Положи этот файл вместе с `linux-mastery-game-design.md` и справочниками (`top-100-linux-commands-devops.md`, `top-120-linux-mastery-devops.md`) в одну рабочую директорию, прикрепи всё и попроси начать с Фазы 1.

---

# Задача

Построить интерактивную браузерную игру для прокачки Linux до уровня уверенного профессионального владения: настоящий интерактивный терминал поверх честно симулированной виртуальной Linux-среды, плюс теоретические квизы для тем, которые нельзя честно симулировать. Без бэкенда, без профилей/аккаунтов, весь прогресс — в localStorage. Работать по фазам, с проверкой после каждой.

# Источник истины

Прочитай полностью `linux-mastery-game-design.md` перед началом — архитектура, схема контента, структура репозитория, разделение Terminal/Theory режимов. Прочитай `top-100-linux-commands-devops.md` и `top-120-linux-mastery-devops.md` — это источник контента для уровней и квизов, не выдумывай вопросы/сценарии с нуля, когда есть готовый проработанный материал.

# Дух этой задачи — прочитай перед тем, как начать

Это не MVP-заглушка "для галочки". Симулятор команд должен ПО-НАСТОЯЩЕМУ поддерживать пайпы, редиректы, флаги команд, реалистичные сообщения об ошибках — если `ls` несуществующей директории, ответ должен быть `ls: cannot access '...': No such file or directory`, а не общая заглушка "ошибка". UI должен выглядеть как продукт, который не стыдно показать, а не студенческий pet-проект на дефолтных компонентах. Если сомневаешься между "сделать быстро и грубо" и "сделать правильно" — выбирай правильно, если это не блокирует прогресс критично. Контент уровней должен быть содержательным и разнообразным, не 5 одинаковых по структуре уровней с разными именами файлов.

# Общие правила

1. Не начинай фазу N+1, пока не выполнены критерии готовности фазы N.
2. После каждой значимой единицы работы — собери и запусти (`npm run dev`), проверь в реальности, не предполагай, что работает.
3. Симулятор команд — ядро проекта. Не срезай углы здесь ради скорости в других местах.
4. Каждый terminal-уровень и каждый quiz-вопрос обязан иметь `relatedReference`/`sourceReference` на конкретный пункт исходного справочника.
5. Не изобретай контент, которого нет в справочниках, для MVP-модулей (1-3, 8) — переноси и адаптируй существующие вопросы/сценарии в игровой формат.
6. Один коммит на фазу: `phase(N): <что сделано>`.
7. Если архитектурное решение из дизайн-документа не работает на практике — объясни, почему, и предложи альтернативу, прежде чем менять.

# Формат отчёта после фазы

```
## Phase N Report
- Implemented: ...
- Verified: <что реально запустил и проверил, не "должно работать">
- Content coverage: <сколько уровней/вопросов реализовано, из какого источника>
- Blockers or deviations from design doc: ...
```

# Фаза 1 — Ядро виртуальной среды

**Директория:** `src/shell/`

- `VirtualFileSystem.ts` — дерево файлов/директорий, права, владелец, время, операции create/read/update/delete/move
- `CommandInterpreter.ts` — парсер: пайпы, редиректы, `&&`/`||`, переменные, глоббинг
- `commands/fileCommands.ts` — `ls` (включая `-la`, `-lh`, `-lt`), `cd`, `pwd`, `cat`, `mkdir`, `touch`, `rm`, `cp`, `mv`, `ln`, `stat`, `file`
- `commands/permissionCommands.ts` — `chmod` (числовой и символьный режим), `chown`
- `commands/textCommands.ts` — `grep` (с `-r`, `-v`, `-i`, `-c`), `find` (по `-name`, `-mtime`, `-size`), `head`, `tail`, `wc`, `sort`, `uniq`, `cut`, `awk` (базовые `{print $N}`), `sed` (базовая `s///`)

**Критерии готовности:**
- [ ] Пайпы реально работают: `cat file.txt | grep pattern | wc -l` даёт корректный результат через цепочку
- [ ] Редиректы реально пишут в виртуальную ФС: `echo test > file.txt` создаёт файл с содержимым, доступным следующей командой
- [ ] Реалистичные сообщения об ошибках для несуществующих путей/недостатка прав
- [ ] Минимум 20 команд из списка реализованы с реальными флагами, не только базовый вызов без аргументов

# Фаза 2 — Терминальный UI

**Директория:** `src/terminal/`

- Интеграция `xterm.js`, подключение к `CommandInterpreter`
- История команд (стрелки вверх/вниз)
- Реалистичный prompt (`user@linux-game:~$`)
- Автоскролл, обработка Ctrl+C (прервать текущий "процесс" в сценариях)

**Критерии готовности:**
- [ ] Можно вводить произвольные команды из фазы 1 и видеть реальный вывод
- [ ] История команд работает между вводами в рамках сессии
- [ ] Внешний вид — не дефолтный чёрный терминал без стилизации, соответствует общей дизайн-системе проекта

# Фаза 3 — Игровой движок и первый модуль контента

**Директория:** `src/game/`, `src/content/modules/01-files-and-permissions.json`

- `LevelEngine.ts` — загрузка уровня, инициализация виртуальной ФС из `initialFileSystem`, проверка `goal` после каждой команды
- `ProgressStore.ts` — сохранение прогресса в localStorage
- `HintSystem.ts` — прогрессивные подсказки со штрафом к XP
- Контент: минимум 12 terminal-уровней в модуле "Файлы и права доступа", основанных на вопросах 1-30 из `top-100-linux-commands-devops.md` и `top-120-linux-mastery-devops.md` (раздел "права доступа и файловая система")

**Критерии готовности:**
- [ ] Полный цикл: выбрать уровень → получить briefing → ввести команды в терминал → движок распознаёт выполнение цели → показывается объяснение и начисляется XP
- [ ] Подсказки реально доступны по клику, с честным штрафом к итоговому XP
- [ ] 12 уровней пройдены вручную самим собой (не только "должны работать по коду") — зафиксировать в отчёте фазы, что каждый лично пройден

# Фаза 4 — Theory Mode

**Директория:** `src/components/QuizCard.tsx`, `src/content/quiz/theory-questions.json`, `src/game/SpacedRepetition.ts`

- Флэшкарты с множественным выбором, объяснением после ответа
- Минимум 40 вопросов, перенесённых из `top-120-linux-mastery-devops.md` (разделы, которые нельзя честно симулировать: systemd, LVM/RAID, память/OOM, безопасность)
- Базовый spaced repetition: вопросы с недавней ошибкой показываются чаще

**Критерии готовности:**
- [ ] Квиз реально работает end-to-end, объяснение показывается после каждого ответа независимо от того, верный он или нет
- [ ] 40+ вопросов загружены и корректно отображаются, каждый со `sourceReference`

# Фаза 5 — Процессы, текст, диски (модули 2-4)

Аналогично фазе 3, но для оставшихся terminal-модулей:
- `commands/processCommands.ts` + `VirtualProcessTable.ts` — `ps`, `kill` над фейковой таблицей процессов
- `commands/diskCommands.ts` — `df`, `du` над виртуальной ФС с заданными размерами
- Контент: минимум 10 уровней на модуль (процессы, текстовые пайплайны, диски)

**Критерии готовности:**
- [ ] Сценарий "найти и убить зависший процесс" работает: `ps aux` показывает фейковый процесс, `kill -9 PID` меняет его состояние, повторный `ps aux` это отражает
- [ ] Минимум 10 уровней на каждый из 3 модулей, лично пройдены и подтверждены в отчёте

# Когда останавливаться и спрашивать

- Реализация конкретной команды в симуляторе оказывается непропорционально сложной относительно пользы (например полноценный regex-движок для grep) — предложи упрощённую, но честно описанную версию вместо того, чтобы тихо забросить
- Схема JSON-контента из дизайн-документа неудобна на практике — предложи изменение и обоснование
- Контента в справочниках объективно не хватает для полноценного модуля — скажи прямо, не растягивай 5 вопросов на 20 искусственными вариациями

Во всех остальных случаях — решай сам, фиксируй решение в отчёте по фазе и продолжай.
